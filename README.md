# AFI 36-2903 Chatbot

An AFI 36-2903 chatbot that helps Airmen find relevant source passages about dress and personal appearance. Using retrieval-augmented generation (RAG), it searches the documents supplied by the user, selects passages related to the question, and displays the original text with file, PDF page, and paragraph references.

**This project was created entirely with AI.** It is an educational project for learning how RAG systems work, including document ingestion, embeddings, retrieval, and language-model integration.(FYI: Yes, this README was also made with AI. I didn't know how to have a new user set it up so I asked AI to help. lol)

The current version uses **evidence quote mode**: Ministral selects passage IDs, and Python displays the source text. Users should read the cited passages and confirm that they apply to their situation and publication edition.

## Features

- Searches PDF, UTF-8 TXT, and Markdown documents.
- Combines semantic search with keyword search.
- Reconstructs numbered policy paragraphs and attaches chapter labels when recognized.
- Applies retrieval filters for uniform and item context.
- Supports short follow-up questions using recent human questions.
- Displays source passages and can decline questions when suitable evidence is not selected.
- Runs from PowerShell or a VS Code task.

## How it works

```text
Documents -> Extract text -> Split into chunks -> Create embeddings -> Save index

Question -> Retrieve and filter passages -> Ministral selects IDs -> Display source text
```

Two models have separate jobs:

| Component | Model | Role |
| --- | --- | --- |
| Python embeddings | `sentence-transformers/all-MiniLM-L6-v2` | Converts document text and questions into search vectors on the CPU. |
| LM Studio | `Ministral 3 3B Instruct 2512` | Selects relevant excerpts from the retrieved passages. |

The Nomic embedding model sometimes listed by LM Studio is not used by the current scripts. The `openai` package connects to LM Studio's local API; no OpenAI account is required for the default setup.

## Requirements

- Windows and PowerShell for the commands below.
- Python 3.14, as used by this project.
- [LM Studio](https://lmstudio.ai/download) with Ministral downloaded and available to its API server.
- VS Code if you want to use the included launch task.
- Internet access for package installation and initial model downloads.

LM Studio can use a supported GPU for inference. Python creates embeddings on the CPU, so a false result from `torch.cuda.is_available()` does not by itself prevent this setup from running.

## First-time setup

### 1. Prepare the Python environment

Open PowerShell in the project root. For the existing installation:

```powershell
Set-Location 'C:\Users\RKo\Code Projects\AFI_36-2903_RAG-System'
```

If you store the project elsewhere, substitute your own path. If the root `.venv` folder does not exist, create it:

```powershell
py -3.14 -m venv .venv
```

Install the dependencies:

```powershell
& '.\.venv\Scripts\python.exe' -m pip install --upgrade pip
& '.\.venv\Scripts\python.exe' -m pip install -r '.\ministral-lmstudio-rag\requirements.txt'
& '.\.venv\Scripts\python.exe' -m pip check
```

These commands use the virtual environment directly, so PowerShell activation is optional. They also avoid changing your PowerShell execution policy.

### 2. Load Ministral and start LM Studio's server

1. Open LM Studio.
2. Find [Ministral 3 3B Instruct 2512 GGUF](https://huggingface.co/lmstudio-community/Ministral-3-3B-Instruct-2512-GGUF).
3. Download the `Q4_K_M` variant for this setup and load it.
4. Enable GPU offload if supported by your machine. Adjust loading settings to fit available memory.
5. Open the Developer tab and start the local API server on port `1234`.

The application's default endpoint is:

```text
http://127.0.0.1:1234/v1
```

Keep LM Studio's server running while using the chatbot. See the [LM Studio server guide](https://lmstudio.ai/docs/developer/core/server) for server setup.

From the project root, list the advertised model IDs:

```powershell
& '.\.venv\Scripts\python.exe' '.\ministral-lmstudio-rag\chatbot.py' --list-models
```

The model ID used by the included VS Code task is `ministral-3-3b-instruct-2512`. If your server advertises a different ID, use that exact ID in the commands and update the task's `--model` argument.

Test generation:

```powershell
& '.\.venv\Scripts\python.exe' '.\ministral-lmstudio-rag\chatbot.py' --model 'ministral-3-3b-instruct-2512' --check
```

The check should print a reply such as `READY`. This verifies model generation; it does not test document retrieval.

### 3. Add documents and build the index

Put your source files in:

```text
ministral-lmstudio-rag/documents/
```

Use the publication edition and supplements you intend to query. The application does not check whether a document is current.

Build the index from the project root:

```powershell
& '.\.venv\Scripts\python.exe' '.\ministral-lmstudio-rag\ingest.py'
```

The first run may download the MiniLM embedding model. When ingestion finishes, it saves `ministral-lmstudio-rag/index.npz`.

Re-run ingestion after adding, changing, or removing documents, or after changing the embedding model or chunking settings. Then restart the chatbot to load the updated index.

## Run the chatbot

### Option A: VS Code task

After completing setup:

1. Open **AFI_36-2903_RAG-System** as the folder in VS Code. This should be the root containing `.vscode` and `.venv`.
2. Start LM Studio's API server.
3. Press **Ctrl+Shift+P**.
4. Select **Tasks: Run Task**.
5. Choose **RAG: Start chatbot**.
6. Enter questions in the task's terminal.

The task selects the virtual-environment Python executable and Ministral model automatically. Enter `/exit` to stop it.

### Option B: PowerShell

With LM Studio running, execute these commands from the project root:

```powershell
& '.\.venv\Scripts\python.exe' '.\ministral-lmstudio-rag\chatbot.py' --model 'ministral-3-3b-instruct-2512'
```

To avoid repeating the model argument in the current terminal session:

```powershell
$env:LM_STUDIO_MODEL = 'ministral-3-3b-instruct-2512'
& '.\.venv\Scripts\python.exe' '.\ministral-lmstudio-rag\chatbot.py'
```

This environment variable lasts for the current PowerShell session. The VS Code task supplies the model argument each time it launches.

## Ask questions and inspect sources

Ask specific questions and name the uniform or item when relevant. For example:

```text
What are the five elements of the standard of dress and personal appearance?
What footwear is authorized with the OCP uniform?
What does paragraph 7.4.1.2 say about low quarters?
What does DAFI 36-2903 govern?
```

Follow-up questions use recent human questions as context. When changing uniforms or topics, state the new context explicitly or enter `/reset`.

| Command | Purpose |
| --- | --- |
| `/sources` | Shows the full passages supplied for the last completed request. |
| `/reset` | Clears recent questions and last-source information. |
| `/exit`, `quit`, or `exit` | Stops the chatbot. |

Keep questions within 800 characters.

The answer displays selected source passages with IDs such as `[1]`. The source list contains all passages supplied to the model, including candidates it may not have selected. Match the answer's IDs to that list.

PDF references use physical file page numbers, which can differ from the numbers printed in the publication. A displayed similarity score ranks semantic matches; it is not an answer-confidence percentage.

## Questions outside the supplied documents

The chatbot does not retrieve the contents of another publication merely because a source references it. For example, a reference to AFI 34-1201 does not supply its general saluting rules.

To query another publication:

1. Add the applicable document to `documents/`.
2. Re-run `ingest.py`.
3. Restart the chatbot.
4. Check the retrieved passages before relying on the response.

Uniform-specific search filters are tailored to DAFI 36-2903. Results from other documents require review, and the application does not automatically resolve conflicts between editions or publications.

## Configuration

Edit `ministral-lmstudio-rag/config.py` to change shared settings.

| Setting | Current value | Purpose |
| --- | --- | --- |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Document and question embedding model. Changing it requires re-ingestion. |
| `CHUNK_TOKENS` | `180` | Ingestion chunk size. Changing it requires re-ingestion. |
| `OVERLAP_TOKENS` | `30` | Shared context between chunks. Changing it requires re-ingestion. |
| `TOP_K` | `3` | Normal maximum number of retrieved candidates. |
| `MAX_NEW_TOKENS` | `512` | Maximum tokens in the model's evidence-selection response. |
| `HISTORY_TURNS` | `3` | Number of recent human questions retained. |
| `MAX_PROMPT_BYTES` | `6000` | Request-size guard measured in UTF-8 bytes, not model tokens. |

LM Studio's model context length is configured separately. If the server rejects a request as too long, reduce the prompt budget or adjust the loaded model's context setting within available memory.

Optional connection settings:

```powershell
$env:LM_STUDIO_BASE_URL = 'http://127.0.0.1:1234/v1'
$env:LM_STUDIO_API_KEY = 'YOUR_LM_STUDIO_TOKEN'
```

Set a real token only when your LM Studio server requires authentication. Keep tokens out of committed project files.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Connection refused or API connection error | Confirm that LM Studio's server is running and the endpoint and port match. |
| Several models are visible | Use the explicit Ministral `--model` argument or the included VS Code task. |
| Unknown model ID | Run `--list-models` and copy the exact ID advertised by your server. |
| Authentication error | Set `LM_STUDIO_API_KEY` to the token required by LM Studio. |
| Missing Python package | Install requirements using the project's `.venv\Scripts\python.exe`. |
| No index found | Run `ingest.py` from the project root. |
| No text extracted | Check whether the PDF is scanned. Apply OCR before ingestion if necessary. |
| Wrong or irrelevant passage | Use `/sources`, ask a more specific question, name the uniform, and try `/reset`. |
| Refusal despite an answer being present | Inspect retrieval. Missing evidence selection or an invalid model response can also cause refusal. |
| Context or request too long | Shorten the question or adjust the request budget and LM Studio context settings. |
| Old documents still appear | Rebuild the index and restart the chatbot. |
| Slow generation or model-loading failure | Inspect LM Studio's GPU offload, loaded models, context length, and available memory. |

## Current limitations

- The model can select an irrelevant passage even though the visible text comes from a real source.
- PDF text extraction does not provide OCR, image interpretation, or reliable understanding of complex tables.
- Follow-up handling and uniform routing rely on heuristics that can retain stale context or exclude applicable passages.
- The application does not verify publication currentness, amendment precedence, or policy applicability.
- This version is a local, single-user terminal application.
- Existing `GROUNDING.md` and `test_grounding.py` describe an earlier implementation and need updating; they do not currently validate evidence quote mode.

Before relying on the chatbot, test questions whose answers you can locate in the document, questions with exceptions or uniform-specific scope, and questions the supplied documents cannot answer. Review the selected text and source references.
